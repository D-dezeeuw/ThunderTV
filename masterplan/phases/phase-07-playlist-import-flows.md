# Phase 07 — Playlist Import Flows

> **Epic goal:** Every way a playlist enters the app — file upload, paste-as-text, URL fetch — works end-to-end through the Phase 06 worker with progress, honest CORS-classified errors, idempotent upserts, and clean cancellation, on every storage tier.
> **Verification:** On the built `dist/`, all three import paths take a fixture playlist to a browsable stored source with live progress; a cross-origin URL without CORS headers shows the specific CORS explanation with working alternatives (not a generic error); importing the same URL twice yields one source; cancelling mid-import leaves storage with no partial source; the storage-matrix suite passes on memory, localStorage, and fake-IndexedDB tiers.

Before this phase the parsing engine exists but nothing feeds it — the app still opens to an empty shell. After it, the first-run import card is the front door: file, paste, and URL imports run through one shared pipeline (`fetch/read → decode → worker → chunked storage writes → source meta commit`), the CORS reality of MASTERPLAN.md §5.2/§8 is designed into the URL path, and Phase 08 has real stored channels to render.

## Completion notes

**Real bugs found and fixed this phase (not deviations — genuine defects caught before they'd have shipped):**

- **`reportOutcome()` swallowed every classified failure except the synthetic `duplicate` shape.** Found via live browser verification, not the unit suite: a URL import against an unreachable host left the UI stuck on "Fetching…" forever, even though the underlying `classifiedFetch` call had already resolved to `cors-or-network` in ~13s. Root cause: the action layer assumed `runImport()` always set `import.errorKind` for every error, but `runImport()` is never even called for a pre-parse classified failure (mixed content, HTTP/CORS/timeout, too-large, invalid M3U) — those return directly from `src/m3u/import.ts`'s entry functions. Fixed by making `reportOutcome()` call `setImportError()` for any non-ok, non-cancelled, non-duplicate outcome. This also means the *unit* test suite's own coverage of `classifyHttpFailure` etc. (thorough, at the pipeline layer) had never actually proven the error reached the DOM — new regression tests in `playlist.actions.spec.ts` assert `import.state`/`import.errorKind` end to end through the trigger functions specifically to close that gap.
- **Cancel did nothing during the fetch stage.** `runImport()`'s own cancellation only ever covers parsing/writing (it isn't called yet during a URL fetch) — there was no fetch-phase cancellation at all until this phase added `activeFetchController` (an `AbortController` threaded through `importPlaylistUrl`'s new `options.signal`). Verified live: Cancel had zero effect ~13s into a hung fetch before the fix, returned to idle within ~1s after.
- **Cancel never reset `import.state` back to idle.** `runImport()`'s cancel branch deleted staged rows but left `import.state` stuck at whatever busy stage it was cancelled from — fixed with a `resetImportState()` call, caught by a direct regression assertion.
- **`StorageTierController` doesn't retry a write across a demotion it causes** (found, not fixed — see Feature 07.9.10 above for the full account and reasoning for leaving it to a future Phase 04 hardening pass).
- **`data-each` must live on the container, not the per-item element.** `<li data-each="...">{{item}}</li>` silently produced a Spektrum console warning and rendered nothing; fixing it to `<ul data-each="...">ated during the first real-browser verification pass, before any commit.

**A real ECMAScript-syntax discovery that shaped every template in this phase:**

`import` is an ECMAScript reserved word. Spektrum's template-expression compiler (`new Function('state','scope', 'with(state) with(scope||{}) { return (EXPR) }')`) rejects any expression that starts with the bare token `import` (`import.state === 'error'`) as a syntax error — verified directly against the vendored engine (`import.state` throws `Unexpected identifier`, `state.import.state` does not, since `import` as a property name *after* a dot is unrestricted). Every one of this phase's `import.*` Spektrum keys is therefore never referenced directly in `index.html`; instead, `src/state/import.selectors.ts` exposes flat, reserved-word-free computed names (`importBusy`, `importDone`, `importStageLabel`, `importRowsReadout`, `importErrorMessage`, `importSummaryHeading`, `importSummaryLines`, `showDuplicateConfirm`, `showLargeConfirm`, `showRetry`, `showRetryViaProxy`) that the markup reads instead — a cleaner design than the `state.import.x` workaround would have been anyway, and now the only one used anywhere in this phase's HTML.
