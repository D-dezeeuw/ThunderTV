# Phase 05 — Spektrum State Architecture

> **Epic goal:** Make Spektrum the app's single state layer — organized store modules, a `defineFn`-only action layer, a debounced persistence bridge to the `StorageAdapter`, and session/channel-state caching — so a reboot restores the last-watched channel row rendered and playable before any playlist re-parse.
> **Verification:** Every mutation in the codebase goes through a `defineFn` action (grep proves no bare `setValue` outside `src/state/` and the sanctioned publishers); the persistence bridge batches dirty keys into one debounced `setMany`; on the built `dist/`, setting a fake active channel + zap history, reloading, and observing the restored session _before_ any heavy load demonstrates the §6.4 boot order on the full and partial tiers; replay is capped in dev and disabled in prod; and the bindDOM state suite passes under `npm test`.
> **Status:** `shipped` · tracker: `current` — Store modules, the persistence bridge and session restore all still hold — `src/state/README.md` is the live reference.

Before this phase, Spektrum holds ad-hoc UI values (`ui.activeView`, `ui.density`, `storage.tier`) written directly by shell code, and nothing survives a reload. After it, `src/state/` owns a modular store (`state/playlist`, `state/player`, `state/epg`, `state/settings`, `state/ui`) mutated exclusively through `defineFn` actions; actions that touch persisted keys mark them dirty and a debounced bridge snapshots them to the storage engine (MASTERPLAN.md §6.3); boot rehydrates saved keys before `run()` and before any heavy load (§6.4); the channel-state cache (last-watched snapshot, capped zap history, per-view UI state) makes session restore instant; time-travel history is capped in dev and off in prod; and bulk imports are documented and enforced as bypassing recorded state entirely. This is the last foundation phase — Phase 06's parser lands into a finished state architecture.

## Completion notes

**Real findings from building this phase:**

- **Spektrum stores dotted-path keys as nested objects in `appState`**, not flat string-keyed properties (`appState['player']?.active`, never `appState['player.active']`). An early draft of `player.actions.ts` read the flat form; caught immediately by re-reading the existing Phase 02-04 pattern (`(appState['storage'] as {...})?.tier`) and fixed to use `getPathObj(appState, key)` throughout.
- **`registerPersistOnHide()`'s original draft removed a differently-named listener than it added** (an inline anonymous arrow for add, a separately-named reference for remove) — `removeEventListener` silently no-ops on a non-identical function reference, so the leak would have been invisible without a targeted spec. Fixed by naming both handlers once and reusing the same reference for add/remove; `persist.spec.ts`'s pagehide/visibilitychange specs now exercise the real listener lifecycle.
- **A genuine Phase 02 bug, found during the migration survey, not introduced by this phase**: the original `connect.detected` computed was re-registered from *inside* a `watch()` callback on every `ui.activeView` change — working, but wasteful (Spektrum's `computed()` already re-derives on dependency change without re-registration). Fixed in the Phase 05 rewrite (`ui.selectors.ts`'s `registerConnectDetectedComputed()`, registered once); regression-tested in `ui.selectors.spec.ts`'s "recomputes correctly across repeated navigations" spec.
- **A duplicate-registration bug was introduced mid-refactor and caught before commit**: `bootstrap.ts` briefly called both the new `registerSelectors()` (which registers `hasNoSources` via `playlist.selectors.ts`) *and* the old `registerEmptyStateComputeds()` from the soon-to-be-deleted `src/ui/empty-state.ts` (which registered the same computed name against the *old*, now-renamed `sources.count` key). Fixed by removing the stale import/call and deleting `empty-state.ts` + its spec, migrating its test coverage into `playlist.selectors.spec.ts` against the renamed `playlist.sourceCount` key.
- **`index.html` still referenced three pre-rename keys** (`sources.count`'s consumer `hasNoSources` was fine since the computed name didn't change, but `demoRows` and `sources.lastPickedLabel` were raw, unrenamed bindings) — caught by grepping the whole file for the old key strings before considering the rename complete, not by a test (there's no spec that renders `index.html` itself yet). Fixed alongside the `data-fn` renames in the same pass.
- **`devtools.ts`'s first draft imported a nonexistent `dumpState` export from `'spektrum'`** — the real pinned API's closest equivalent is `describe()` (returns the full manifest). Caught by `tsc`, fixed immediately.
- **Spektrum's `data-value` coercion is primitives-only** (`null`/`''` → `undefined`, `"true"`/`"false"` → boolean, a numeric string → number, everything else → the raw string — verified by decompiling the vendored `spektrum.min.js`'s `yt()` helper).
